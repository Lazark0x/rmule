# Parity: eD2k server UDP

Audited **2026-10-02** against the code and the committed fixtures: every row's
status is read from the rmule site it names, and every evidence path exists in
the repository. Schema, status values and the evidence rule:
[README.md](README.md). Cites pin aMule 2.3.3 (`4e8f2b3`).

Direction is from rmule's perspective: `E` = rmule emits, `C` = rmule consumes,
`B` = both. All aMule cites are SHA permalinks into `amule-project/amule@4e8f2b3`
and point at the handler or sender, not the opcode `#define`.

This is the client↔server **UDP** surface: eMule's breadth path, fired fire-and-forget
at every server in the list (not just the one TCP-connected server). Global source
discovery, global search and the status/description chain are specified by
[ADR-0051](../../adr/0051-server-udp-engine-for-global-sources-and-search.md) and
[ADR-0052](../../adr/0052-server-status-chain-and-capability-store.md).

Opcodes amuled 2.3.3 *defines but never emits or consumes* are not rows; they are
listed under "Defined-but-dead opcodes" at the foot of this file.

### Defined-but-dead opcodes (not rows)

emit or consume site — confirmed by whole-tree grep (only the header matches).

(the header is its only reference — grep-confirmed), yet it is kept as a **row** above
(Global source discovery), not here, because rmule implements it and eMule/eserver
emit+consume it — see that row's note.
