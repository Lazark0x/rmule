# Parity: Kad UDP

Audited **2026-10-02** against the code and the committed fixtures: every row's
status is read from the rmule site it names, and every evidence path exists in
the repository. Schema, status values and the evidence rule:
[README.md](README.md). Cites pin aMule 2.3.3 (`4e8f2b3`).

Direction is from rmule's perspective: `E` = rmule emits, `C` = rmule consumes,
`B` = both. All aMule cites are SHA permalinks into `amule-project/amule@4e8f2b3`
and point at the handler or sender, not the opcode `enum`.

This is the **Kad UDP** surface: eMule's serverless DHT, spoken over the client
UDP socket under two protocol bytes — `OP_KADEMLIAHEADER 0xE4` (plain) and
`OP_KADEMLIAPACKEDPROT 0xE5` (zlib-packed). The single dispatch is
`CKademliaUDPListener::ProcessPacket` ([KademliaUDPListener.cpp#L213](https://github.com/amule-project/amule/blob/4e8f2b3c3f90cda23765730546b04c684a92e4f5/src/kademlia/net/KademliaUDPListener.cpp#L213));
every emit is a `SendPacket`/`SendMyDetails`/`SendNullPacket` helper. Two opcode
enums exist: **Kad1** (`KademliaV1OPcodes`, legacy) and **Kad2**
(`Kademlia2Opcodes`). aMule 2.3.3 advertises `KADEMLIA_VERSION 0x08`
([kad2/Constants.h#L29](https://github.com/amule-project/amule/blob/4e8f2b3c3f90cda23765730546b04c684a92e4f5/src/include/protocol/kad2/Constants.h#L29))
and speaks Kad2 to every live contact; the Kad1 opcodes survive only as
backward-compat paths to pre-Kad2 (contact-version < 3/4) nodes that are extinct
in the live network — see the "Legacy Kad1" table.

rmule's Kad node is the sans-I/O `KadNode` in `rmule-kad`
([ADR-0043](../../adr/0043-kad-full-node-for-source-discovery.md)), run by
`rmule-net/src/kad/` on the shared client-UDP socket (peer-udp.md). Keyword
search and publish follow [ADR-0062](../../adr/0062-symmetric-kad-keyword-search-and-publish.md),
notes [ADR-0063](../../adr/0063-kad-notes-by-empty-storer-parity.md), liveness
and anti-flood [ADR-0064](../../adr/0064-kad-liveness-and-verified-contacts.md),
the firewall self-check [ADR-0058](../../adr/0058-kad-firewall-self-check.md),
buddies and callbacks [ADR-0061](../../adr/0061-low-id-callback-route-tree-and-buddies.md),
and the crypt layer [ADR-0046](../../adr/0046-per-datagram-udp-obfuscation-layer.md).
Send-side crypt is off unless `CoreSettings::obfuscation` is set; receive is always
dual-path.

`OP_DIRECTCALLBACKREQ 0x95` is defined in `kad2/Client2Client/UDP.h` but travels
on the **eMule extended UDP** protocol byte (`OP_EMULEPROT 0xC5`), not `0xE4` —
it is a peer-UDP opcode and is rowed in peer-udp.md.

### Defined-but-dead / silently-dropped opcodes (not rows)

Unlike the eD2k surfaces (which leave dead opcodes to the unknown-opcode path),
aMule 2.3.3 gives the fully-deprecated Kad1 opcodes an **explicit no-op `case`**
in `ProcessPacket` ([#L352](https://github.com/amule-project/amule/blob/4e8f2b3c3f90cda23765730546b04c684a92e4f5/src/kademlia/net/KademliaUDPListener.cpp#L352)–[#L363](https://github.com/amule-project/amule/blob/4e8f2b3c3f90cda23765730546b04c684a92e4f5/src/kademlia/net/KademliaUDPListener.cpp#L363)):
recognized only to be dropped without a reply, never emitted anywhere in the
tree (grep-confirmed). No behavior, so not parity rows.
